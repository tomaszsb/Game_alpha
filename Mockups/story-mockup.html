Story-as-Composed-Stories — Layout Options

Proposal: a space's "story" is composed of per-action narratives. Each action's narrative is also reused inside that action's modal as flavor text — single source of truth, no duplication. Action order recommended: E (Expeditor — push usage) → W (Work — scope) → B (Bank — money in) → I (Investor — money in) → L (Life — usually auto, rarely shown).

Source of truth (Spaces.csv per-action narrative columns)

These columns already exist. Today only `Event` is shown to the player; per-action narratives are dormant.

Player just landed on ARCH-FEE-REVIEW. The space has 4 actions (E, W, B, I). How do we present the composite story?

OPTION A

Each action is a colored card showing its narrative + button. Player scrolls top-to-bottom in recommended order.

What I'd recommend (and why)

Landing-on-space: Option A — Stacked Action Cards. The composite-story idea is the whole point: showing all narratives at once is the feature. Tabs/accordion hide the very thing we're trying to surface. Yes, it's tall — but spaces typically have 2–4 actions, not 10.

Per-action modal: Option A — Tinted Blockquote. Same color token as the action card on the landing modal → the player sees the same narrative in the same color, building a "this is the story for this card type" mental model. Option B is too quiet; Option C is too noisy.

Drop the standalone `story` field? Yes. Spaces.csv keeps `Event` as a vestigial header (or we remove it). The composed view IS the story. One source per action, used in two places.

  • For Required vs Optional actions — is the meta label enough, or do we want a stronger visual treatment (e.g., a red ring on Required-but-not-yet-done)?
